# Switch MAC Address Table

For this exercise, you will investigate how a switch creates and uses a MAC address table to switch frames. First, you will generate a bit of traffic. 

+ Open a command window on 172.16.31.2 and  enter ``ping 172.16.31.4``.
+ Similarly, open a command window on 10.10.10.2 and  enter ``ping 10.10.10.3``.
+ Click *Switch1* and then the CLI tab. Enter the ``show mac-address-table`` command. Make sure you understand the entries in the table.  
![MAC Address Table](./img/mac.png)

+ Click *Switch0*, then the CLI tab. Enter the ``show mac-address-table`` command.  
  **Question:** On *Switch0*, why are two MAC addresses associated with the same port?

# ARP in Remote Communication

+ Click 172.16.31.2 and open the Command Prompt.
+ Enter ``ping 10.10.10.1`` followed by ``arp –a`` to view the ARP table.  
**Question:** What is the IP address of the new ARP table entry?

+ Enter ``arp -d`` to clear the ARP table and switch to Simulation mode.
+ Repeat the ping to 10.10.10.1.  
  **Question:** How many PDUs appear?

+ Click *Capture/Forward*. Click the PDU that is now at *Switch1*.  
  **Question:** What is the target destination IP destination address of the ARP request? Why is the destination IP address not 10.10.10.1?

+ Switch to *Realtime* mode. 
+ Click *Router1* and then the *CLI* tab.
+ Enter the ``show arp`` command.  
  **Question:** Is there an entry for 172.16.31.2?
What happens to the first ping in a situation where the router responds to the ARP request?
