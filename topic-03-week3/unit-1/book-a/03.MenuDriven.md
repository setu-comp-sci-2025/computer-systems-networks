# **case** 

You might want a user to confirm **yes** or **no** as an input from user

**YesOrNo.sh**

```bash
#!/bin/bash

echo -n "Do you agree with this? [y or n]: "
read word
case $word in

        [yY] | [yY][Ee][Ss] )
                echo "Agreed"
                ;;

        [nN] | [n|N][O|o] )
                echo "Not agreed, you can't proceed the installation";
                exit 1
                ;;
        *) echo "Invalid input"
            ;;
esac
```

Execute the script and you should get the following:

```bash
$ ./YesOrNo.sh
Do you agree with this? [y or n]: YES
Agreed
```

## PRACTICE: example of **select** and **case**

1. Offer a menu to the user, 
2. takes their input and 
3. execute the commands

```bash
 #!/bin/bash

echo "Enter a number to indicate Which Operating System you use?"

select os in Lubuntu Mint Windows8 Windows10 Windows11 Mac
do
    case $os in
        "Lubuntu" | "Mint")
            echo "I also use $os ..!"
            ;;

        "Windows8" | "Windows10" | "Windows11")
            echo "Why don't you try Linux..?"
            ;;

        "Mac")
            echo "Fancy that, a %os!"
            ;;
        *)
            echo "Invalid option. Program will exit now."
            break
            ;;
    esac
done 
```

# PRACTICE: Another menu driven script

You can create simple menus using **select** and **case** 

```bash
#!/bin/bash
# Bash Menu Script Example

PS3='Please enter your choice: '
options=("Add" "Search" "Quit")
select opt in "${options[@]}"
do
    case $opt in
        "Add")
            echo "you chose to add a new record"
            ;;
        "Search")
            echo "you chose to search for record(s)"
            ;;
        "Quit")
            break
            ;;
        *) echo "invalid option $REPLY";;
    esac
done
```

# Error checking

This is where you should now be making use of error checking via loops and conditional statements:

What do you want to happen if a user enters an **unexpected character** 
+ Do you decide the script should exit back to command prompt? 
+ or repeat the menu, 
+ or ask them what the user what they would like to do via more menu options?

What if they want to **exit** at any stage? 
+ Could the case insensitive letter Q be their way to do this, 
+ or pressing "ESC" on the keyboard? 

This is the programmers choice but ensure the end user understands what **their choices** are throughout

# EXERCISE:

Amend the **menu** script that will welcome users to the program by name and offer them the following options to choose from:

1) Add a new record
2) Search for a record
3) Delete a record
4) Exit

where
-  menu option `1) Add a new record` will run a script called `add.sh`  that simply returns back to STDOUT (the screen) **WORK IN PROGRESS: you will be able to add records here** and offer users an option to return back to the menu 
-  menu option `2) Search for a record` will run a script called `search.sh` that simply returns back to STDOUT (the screen) **WORK IN PROGRESS: you will be able to search for existing records here** and offer users an option to return back to the menu 
- menu option `3) Exit` This option will indicate to users that they will exit the program and return back to the command prompt. Here, make use of the `sleep` command to exit

```bash
#!/bin/bash
# Author: .....
# Script Description: Bash Menu Script Example

PS3='Please enter your choice: '
options=("Add" "Search" "Delete" "Exit")
select opt in "${options[@]}"
do
    case $opt in
        "Add")
            ./add.sh
            ;;
        "Search")
            ./search.sh
            ;;
        "Delete")
            ./remove.sh
            ;;
        "Exit")
            echo "You chose to exit. Bye!"
            break
            sleep 1
            ;;
        *) echo "invalid option $REPLY";;
    esac
done
```
