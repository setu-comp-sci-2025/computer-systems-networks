# Optional: Raspberry Pi Connect

Using SSH as descibed previously will only let you connect to you raspberry pi within your home network. This step shows how to set up **Raspberry Pi Connect Lite** so you can use a **remote shell in the browser**. This will allow you to remotely connect to your RPi from anywhere (once it's booted and connected of course).

---

## What is Raspberry Pi Connect

- **Raspberry Pi OS Lite** supports **remote shell access** through Raspberry Pi Connect (browser-based terminal).

---

## 1) Install Raspberry Pi Connect Lite (if not already installed)

Connect to your Raspberry Pi using Secure Shell as described previously :

```bash
sudo apt update
sudo apt install rpi-connect-lite
```

---

## 2) Start Connect on the Pi

```bash
rpi-connect on
```

This starts (and enables) Raspberry Pi Connect on your RPi. 

---

## 3) Create a Raspberry Pi Connect account (Raspberry Pi ID)

You need a **Raspberry Pi ID** to use Raspberry Pi Connect.

### Option A: Create it during sign-in (easiest)
When you open the Connect sign-in page (next step), choose **“create one for free”** if you don’t already have a Raspberry Pi ID.

### Option B: Create it first
- Go to the Raspberry Pi ID sign-up page in your browser (linked from the Connect sign-in flow).
- Sign up with your email and password.
- Verify your email address (if prompted).

---

## 4) Link your Pi to your Raspberry Pi Connect account

On the Raspberry Pi terminal:

```bash
rpi-connect signin
```

This prints a verification URL like:

```text
Complete sign in by visiting https://connect.raspberrypi.com/verify/XXXX-XXXX
```

Open that URL on any browser, sign in with your **Raspberry Pi ID**, and complete the linking process. This associates your Pi with your Connect account.

---

## 5) Access your Pi from a browser

- Visit **Raspberry Pi Connect** in your browser (`connect.raspberrypi.com`)
- Sign in with your Raspberry Pi ID
- Your linked device should appear in the device list
- On OS Lite, choose **Remote shell** to open a browser-based terminal session.

---

## 6) Make it survive reboot (recommended on headless/Lite)

Because Connect runs as a **user-level service**, headless systems may need **user lingering** enabled so the service runs after reboot even when you haven’t logged in locally.

Enable lingering:

```bash
sudo loginctl enable-linger $USER
```

Check lingering status:

```bash
loginctl show-user $USER | grep Linger
```

You want to see:

```text
Linger=yes
```

---

## 7) Verify status and troubleshoot

### Check Connect status
```bash
rpi-connect status
```

### Check whether the user service is enabled/running
```bash
systemctl --user status rpi-connect
systemctl --user is-enabled rpi-connect
```

### Confirm OS version (must be Bookworm or later)
```bash
cat /etc/os-release
```

### Common issues
- **Used `sudo rpi-connect signin`** → run it without `sudo` instead (user-level service mismatch)
- **No internet / wrong system time** → TLS/sign-in can fail
- **No lingering enabled on headless Pi** → service may not come back after reboot until local login

---

## Quick command summary (Lite)

```bash
sudo apt update
sudo apt install rpi-connect-lite
rpi-connect on
rpi-connect signin
sudo loginctl enable-linger $USER
rpi-connect status
```
